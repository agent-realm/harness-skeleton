## 2. Scopes and precedence

- Two scopes: global `~/.pi/agent/settings.json`, project `.pi/settings.json` ("Project (overrides global)") [L-docs/settings].
- Merge: nested objects merged one level deep; primitives **and arrays** (e.g. `enabledModels`) replaced by the project value (obs) [L-dist/core/settings-manager.js:9-31 `deepMergeSettings`]. Docs show the object-merge example only [L-docs/settings "Project Overrides"].
- Exceptions: resource arrays (`packages`, `extensions`, `skills`, `prompts`, `themes`) are read per scope and loaded from both (obs) [L-dist/core/package-manager.js:682-683,723-724]; the same package in both scopes is deduped by identity, project entry wins [L-docs/packages "Scope and Deduplication"]. Global-only keys: `defaultProjectTrust`, `httpProxy` [L-docs/settings].
- **Project trust gate (since 0.79.0)** [L-CL 0.79.0]: project `.pi/settings.json`, `.pi` resources, `.pi/SYSTEM.md`/`APPEND_SYSTEM.md`, project `.agents/skills`, and project packages load only after trust. Interactive mode prompts; `-p`/json/rpc use `defaultProjectTrust` (`ask`=decline, `never`, `always`); `--approve`/`-a`, `--no-approve`/`-na` override per run; `/trust` writes `trust.json`; closest saved decision on current or parent path wins [L-docs/security; L-README "Project Trust"]. Context files (`AGENTS.md`/`CLAUDE.md`) load regardless of trust [L-docs/security].
- No managed/enterprise policy scope found (searched settings.md, security.md, README).
- **Upstream 1.0.x:** resource lists are "combined" across scopes; `defaultTools` supports `+name`/`-name` layering of project over user; `sessionDir` is read before trust [U-settings; U-configuration].

## 3. Instructions (context files, system prompt)

- Files: `AGENTS.md` or `CLAUDE.md` [L-README "Context Files"]. Per directory exactly one file is taken, first match in order `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`, `CLAUDE.MD` (obs) [L-dist/core/resource-loader.js:30].
- Locations and order: global `<agent-dir>/AGENTS.md` first, then every ancestor from filesystem root down to cwd (walk goes to `/`, not stopped at git root), all concatenated [L-README; obs L-dist/core/resource-loader.js:46-74].
- Injection format: wrapped as `<project_context>` with one `<project_instructions path="...">` per file, appended after the base prompt and `APPEND_SYSTEM` text, before the skills list, followed by current date and cwd (obs) [L-dist/core/system-prompt.js].
- No `@path` import/include syntax: files are read verbatim (obs; not found in docs, searched README/usage "Context Files").
- System prompt: `.pi/SYSTEM.md` (project, trust required) **or** `~/.pi/agent/SYSTEM.md` replaces the default; `APPEND_SYSTEM.md` appends; project file wins over global, never both (obs) [L-README "System Prompt"; L-dist/core/resource-loader.js:749-768]. `--system-prompt <text|file>` overrides SYSTEM.md discovery; `--append-system-prompt` (repeatable) overrides APPEND_SYSTEM.md discovery (obs) [L-dist/core/resource-loader.js:333-336; L-help].
- Even with a custom system prompt, context files and the skills list are still appended [L-README "Other Options"].
- Disable: `--no-context-files`/`-nc` [L-help].
- Extensions can rewrite the prompt per turn via `before_agent_start` [L-docs/extensions].
- **Upstream 1.0.x:** `AGENTS.override.md` replaces `AGENTS.md`/`CLAUDE.md` in the same directory only (0.84.0) [U-configuration; U-CL 0.84.0].

## 8. MCP servers

**0.80.2: not supported natively, deliberately.**
- Documented stance: "**No MCP.** Build CLI tools with READMEs (see Skills), or build an extension that adds MCP support." [L-README "Philosophy"]; "It intentionally does not include built-in MCP, sub-agents, permission popups, plan mode, to-dos, or background bash" [L-docs/usage "Design Principles"].
- Rationale: MCP servers cost 7-9% of context up front (Playwright MCP 13.7k tokens / 21 tools; Chrome DevTools MCP 18.0k / 26 tools), results must transit the context window (poor composability), hard to extend; alternative is small CLI scripts plus a README the agent reads on demand (~225 tokens for a browser toolkit) [B-MCP; B-PI].
- Workarounds documented: skills wrapping CLI tools [L-docs/skills]; an extension registering tools ("MCP server integration" listed under What's possible) [L-README Extensions]; third-party package (e.g. `pi-mcp-adapter`, named in [U-mcp]). `mcporter` not mentioned in any doc or the MCP post (searched README, docs, [B-MCP]).

**Upstream 0.99.0 (2026-09-29) reversed this: MCP is built in** [U-CL 0.99.0; U-mcp]:
- Built-in extension `builtin:mcp` (disable with `"extensions": ["-builtin:mcp"]` or `pi config`), stdio + streamable HTTP (SSE rejected), OAuth (dynamic registration, CIMD, RFC 9207/9728/8414), tokens in `<agent-dir>/mcp-auth.json`, logs in `<agent-dir>/mcp.log`.
- Config: `<agent-dir>/mcp.json` and `.pi/mcp.json` (trust-gated), `{"mcpServers": {...}}` shape "matches other MCP clients" (Claude Desktop/Code entries copy as-is); project entry replaces same-name user entry, or overrides only `enabled`/`exposure`/`toolExposure` when it lacks `command`/`url`.
- CLI: `pi mcp add|remove|list|login|logout` (`-l` for project), `/mcp` in session; `pi mcp list` exits 1 on invalid/unconnected servers [U-cli "MCP commands"].
- Tools named `mcp__<server>__<tool>`; exposure modes `codemode` (default: reachable only from the QuickJS `codemode` tool), `deferred` (via `tool_search`), `direct`, `hidden`; resources via `list_mcp_resources`/`read_mcp_resource` [U-mcp].
- MCP calls pass through `tool_call`/`tool_result`, so permission extensions apply [U-mcp "Permissions"].
- The upstream README no longer carries the "No MCP" philosophy line [U README fetched 2026-10-04].
- Consequence for the standard: pi >= 0.99 can satisfy "MCP required"; pi 0.80.2 (this install) cannot without an extension. Default exposure is not "declare every tool to the model", which differs from Claude Code.

## 12. Permissions / approvals / sandbox

- No permission prompts, by design: "**No permission popups.** Run in a container, or build your own confirmation flow with extensions" [L-README "Philosophy"]. Author: "pi runs in full YOLO mode ... No permission prompts for file operations or commands"; other tools' safety measures are "mostly security theater" [B-PI].
- No built-in sandbox; "Real isolation needs to come from the operating system or a virtualization/container boundary" [L-docs/security "No Built-in Sandbox"]. Patterns: Gondolin micro-VM extension, plain Docker, OpenShell [L-docs/containerization].
- Project trust is "only an input-loading guard", not a sandbox [L-docs/security].
- Coarse capability control: `--tools` allowlist, `--exclude-tools`, `--no-tools`, `--no-builtin-tools` (e.g. read-only mode `--tools read,grep,find,ls`) [L-help].
- Extension gating examples: `permission-gate.ts` (confirm dangerous bash), `protected-paths.ts`, `confirm-destructive.ts`, `dirty-repo-guard.ts`, `sandbox/`, `gondolin/` [L-docs/extensions "Examples Reference"; L-ex].
- No allow/deny rule language in settings (obs: no `permissions` key).
- **Upstream 1.0.x:** unchanged stance ("does not ask for approval before every tool call") [U-security]; MCP annotations (`readOnlyHint`, `destructiveHint`) exposed to permission extensions [U-mcp].

## 17. Headless / non-interactive

- Modes: `-p/--print` (text, final assistant text to stdout; merges piped stdin), `--mode json` (JSONL: session header then `AgentSessionEvent`s), `--mode rpc` (strict LF-framed JSONL commands on stdin, `{type:"response",success,...}` + events on stdout; extension UI dialogs proxied over the protocol), SDK (`createAgentSession`, `createAgentSessionRuntime`, `runPrintMode`, `runRpcMode`) [L-README "Programmatic Usage"; L-docs/json; L-docs/rpc; L-docs/sdk].
- RPC commands include `prompt`, `steer`, `follow_up`, `abort`, `new_session`, `get_state`, `get_messages`, `set_model`, `cycle_model`, `get_available_models`, `set_thinking_level`, `compact`, `bash`, `get_session_stats`, `export_html`, `switch_session`, `fork`, `clone`, `get_last_assistant_text`, `set_session_name`, `get_commands` [L-docs/rpc].
- Exit codes: not documented in 0.80.2 docs (searched all docs for "exit code"). Observed [L-dist/modes/print-mode.js; L-dist/main.js]: print text mode exits **1** when the last assistant message has `stopReason` `error`/`aborted` or on a thrown error; **JSON mode exits 0 even if the assistant errored** (only a throw gives 1); SIGTERM -> 143, SIGHUP -> 129; unknown model -> 1 [L-dist/core/model-resolver.js:435].

- **Upstream 1.0.x:** exit semantics now documented (print nonzero on error/aborted; JSON does not) [U-cli-integration]; redirected stdin/stdout auto-selects print mode [U-cli]; `message_update` events carry deltas only (0.84.0 breaking) [U-CL]; `pi auth check` 0/1/2 and `pi mcp list` 1 exit codes [U-cli].

## Surprises / things that do not map onto Claude Code's model

- **MCP flipped five days ago.** 0.80.2 (installed) has no MCP and the docs say so as philosophy; 0.99.0+ ships MCP as a built-in, disableable extension with a Claude-compatible `mcpServers` JSON shape. A standard that requires MCP must pin a minimum pi version (>= 0.99.0) or accept an extension as the provider. Default exposure (`codemode`: tools reachable only from a JavaScript sandbox tool) means "MCP tool visible to the model" is not the default.
- **No permission system at all.** No allow/ask/deny rules, no approval prompts, no settings key; gating is TypeScript in `tool_call`. A harness-neutral `permissions` block has no declarative target; the closest declarative lever is the tool allowlist (`--tools`, upstream `defaultTools`).
- **Hooks are code, not config.** Every hook is a TypeScript handler; there is no `command` hook type. A standard expressing hooks as shell commands needs a generic shim extension on pi. Pre-0.87 there is no Stop-with-continue equivalent; `Notification` and `SubagentStop` have no counterparts.
- **No subagents, no plan mode, no todos, no background bash** by stated design; all are extension territory.
- **One env var does not move everything.** `PI_CODING_AGENT_DIR` moves settings, auth, sessions, resources, trust, packages, but `~/.agents/skills` stays tied to `$HOME`, and context files are walked from cwd to `/`. An isolated "playbook" install still sees the user's `~/.agents/skills` and every ancestor `AGENTS.md`/`CLAUDE.md`.
- **`CLAUDE.md` is a fallback, not an equal.** Per directory, `AGENTS.md` wins and `CLAUDE.md` is ignored if both exist; `@import` lines are passed verbatim (no expansion). Claude Code `.claude/skills` and `.claude/settings.json` are not read.
- **Project config is trust-gated, instructions are not.** Unlike Claude Code's workspace trust, non-interactive pi silently ignores project `.pi/` unless `--approve` or `defaultProjectTrust: "always"`; a conformance suite must pass `-a` explicitly.
- **Model switches mutate global settings in 0.80.2.** `/model`, Ctrl+P and thinking changes rewrite `defaultProvider`/`defaultModel`/`defaultThinkingLevel` in the global file; upstream made them session-scoped in 0.84.3. A standard that treats global config as declarative must expect drift on older pi.
- **Mixed array semantics across scopes**: plain setting arrays (e.g. `enabledModels`) are replaced by the project value, while resource arrays are loaded from both scopes; upstream `defaultTools` adds a third rule (`+name`/`-name` layering). A standard's "merge" rule needs per-key mapping.
- **Status line is an extension API** (`setStatus`/`setFooter`), not a command in settings.
- **Exit codes differ by mode**: print mode returns 1 on model error, JSON mode returns 0. A conformance runner using JSON mode must parse events for failure.
- **Release velocity**: about 31 releases in the last 3 months, with breaking notes most minors; any mapping should cite a pinned version.
- **Package identity moved**: `@mariozechner/pi-coding-agent` -> `@earendil-works/pi-coding-agent`; repo `badlogic/pi-mono` -> `earendil-works/pi`.
- **Event names move between patch releases**: `agent_settled` arrived in 0.80.4, so an extension written for it receives no such event on 0.80.2.
