# Add a session adapter

**Goal:** read a new harness's sessions.

Session readers live in [`packages/harness-session-adapters/`](../../packages/harness-session-adapters/), a
package of their own that `hs` and memhouse both use. One reader per harness implements the
`sessions` contract's four operations: `describe`, `list`, `read`, `derive`. The package holds
the one implementation of `host` and `harness_path`, and imports nothing from `hs`.

1. **Read the interface:**
   [`packages/harness-session-adapters/docs/adapter-interface.md`](../../packages/harness-session-adapters/docs/adapter-interface.md)
   and the package's [`AGENTS.md`](../../packages/harness-session-adapters/AGENTS.md).
2. **Make fixtures, never captures of a real store.** A fixture is generated by the harness's
   `generate.js`, or a capture of a synthetic session, scrubbed: no real path, address, host,
   model name or credential. `test/public-fixtures.test.js` enforces this.
3. **Pass the conformance lists.** The package's conformance engine runs the session contracts'
   adapter-side lists against every fixture (`npm test` in the package).
4. **Wire it into `hs`.** `hs` finds a reader through the package's `ADAPTERS`. A harness with a
   reader and no driver answers the `sessions-only` profile: `describe`, `detect` and the three
   `sessions.*` operations.

Changes to the package go through its maintainer. Open the PR in this repository.
